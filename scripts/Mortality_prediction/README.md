# Five-year mortality prediction and clinical translation

This module evaluates whether current affective-functional status and its longitudinal history improve five-year all-cause mortality risk stratification in ageing cohorts.

## Scope

The module contains two linked analyses:

1. The main five-year mortality prediction workflow, which compares current scores with continuous history and deviation terms.
2. The clinical translation workflow, which evaluates adults aged 50–64 years with at least one prior functional measurement and performs external calibration transportability analysis.

The clinical translation workflow uses a fixed HRS development model. External analyses do not re-estimate history or deviation coefficients. A cohort-specific calibration intercept is updated only in the dedicated recalibration stage.

## Main prediction workflow

The main prediction workflow uses the earliest eligible landmark at or after age 50 years for each participant.

- Outcome: all-cause mortality within five years.
- Development: 70% participant-level split of HRS.
- Internal validation: remaining 30% of HRS.
- External evaluation: MHAS and SHARE.
- Sensitivity evidence: ELSA.
- Support-only evaluation: CHARLS.
- Model 0: sex, standardized education and calendar year.
- Model 1: Model 0 plus current affective and functional scores.
- Model 2: Model 0 plus affective history, affective deviation, functional history and functional deviation.

HRS coefficients and cumulative baseline hazards are frozen for internal and external evaluation. The workflow reports five-year AUC, Brier score, calibration, grouped calibration, nested model comparisons and paired participant-level bootstrap differences.

## Clinical translation workflow

The clinical translation workflow uses:

- age 50–64 years at landmark;
- `prior_n >= 1`;
- five-year all-cause mortality;
- continuous history and deviation terms as the primary model;
- a descriptive high historical functional burden indicator based on the cohort-specific H_F P75;
- HRS development as the coefficient development cohort;
- HRS internal validation and external cohort evaluation when event support is available.

The clinical translation workflow reports event support before model fitting. A zero-event group is retained as non-estimable and is never treated as evidence of successful validation.

## External recalibration

The recalibration stage uses the HRS development coefficients without modification. For each evaluation cohort and model, it reports:

- observed five-year risk using Kaplan–Meier and inverse-probability-of-censoring weighting;
- mean predicted risk before recalibration;
- calibration-in-the-large before recalibration;
- calibration slope;
- cohort-specific recalibration intercept;
- mean predicted risk after intercept updating;
- Brier score before and after recalibration;
- decile-level calibration data and calibration plots.

The recalibrated probability is calculated as:

```text
logit(P_recalibrated) = logit(P_original) + cohort-specific intercept
```

Only the intercept changes. The history, deviation and covariate coefficients remain fixed. This stage is a transportability analysis and does not establish a universally calibrated or directly deployable clinical tool.

## Input contract

The scripts require the locked landmark dataset generated by `01_build_age50_landmark_dataset.R`:

```text
results/mortality_prediction/landmark/age50_landmark_dataset.rds
```

The dataset must contain:

```text
cohort, subject_id, split, prior_n, start_age, end_age, event,
followup, time5, event5, observed5, current_A, current_F,
H_A, D_A, H_F, D_F, sex, education, calendar_year
```

Participant-level input data, identifiers, dates, genotypes and controlled external resources remain outside this repository.

## Running the workflows

From the repository root, create the local configuration file:

```r
file.copy("config/config.example.R", "config/config.R")
source("config/config.R", encoding = "UTF-8")
```

The configuration file must define `CLINICAL_LANDMARK_INPUT`, `CLINICAL_PRIOR1_OUTPUT_ROOT` and `CLINICAL_RECALIBRATION_OUTPUT_ROOT`. The default example places the landmark input under `results/mortality_prediction/landmark/`.

Run the existing prediction workflow:

```r
source("run_mortality_prediction.R", encoding = "UTF-8")
```

Run the clinical translation and recalibration workflows together:

```r
source("run_clinical_translation.R", encoding = "UTF-8")
```

Run the same stage through the global dispatcher:

```r
Sys.setenv(DCV_RUN_PIPELINE = "clinical_translation")
source("run_all.R", encoding = "UTF-8")
```

To run both the mortality prediction and clinical translation stages in sequence:

```r
Sys.setenv(
  DCV_RUN_PIPELINE = paste(
    "mortality_prediction",
    "clinical_translation",
    sep = ","
  )
)
source("run_all.R", encoding = "UTF-8")
```

## Reproducibility

- All project paths are defined through `config/config.R` or environment variables.
- No user-specific absolute paths are embedded in the analysis scripts.
- The landmark input is checked for required fields and duplicate participants.
- Age and prior-measurement eligibility are applied before model fitting.
- HRS development coefficients are frozen before external evaluation.
- Calibration intercept updating is isolated to the recalibration stage.
- Fixed seeds are used for bootstrap procedures where applicable.
- Analysis locks record the input path, population definition and model handling.
- Results directories are excluded from Git through `.gitignore`.

Full numerical reproduction requires authorised access to the cohort datasets and other controlled resources listed in `DATA_ACCESS.md`.
